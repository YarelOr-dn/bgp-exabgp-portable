# BGP Tool - Config Generation and Apply

## Reserved IPs

- **ExaBGP side (server):** `100.70.0.32` (in mgmt VLAN). ExaBGP `local-address` stays `100.64.6.134` (server OOB; firewall routes to inband).
- **Device side:** `100.70.0.206` (PE-4 IP on ge100-18/0/6.999 sub-if).
- Both overridable if user specifies another address.

## Config Templates

### DNAAS Leaf

```
interfaces
  bundle-X.999
    admin-state enabled
    description "inband-v999-to-<target_device>"
    l2-service enabled
    vlan-id 999
  !
!
network-services
  bridge-domain
    instance g_mgmt_v999
      interface bundle-X.999
      !
    !
  !
!
```

### Target Device (DNOS)

**Dynamic AFI block:** Generate one `address-family` block per user-selected AFI. Variable `selected_afis` comes from the wizard's AskQuestion step (e.g. `["ipv4-unicast", "ipv4-flowspec"]`). Use `device_ip` = 100.70.0.206 (PE-4 default) unless user overrides.

```
interfaces
  bundle-Y.999
    admin-state enabled
    description "Inband mgmt for BGP peering"
    ipv4-address <device_ip>/24
    vlan-id 999
  !
!
protocols
  static
    address-family ipv4-unicast
      route 100.64.0.0/20
        next-hop 100.70.0.254
      !
    !
  !
  bgp <asn>
    neighbor 100.64.6.134
      remote-as 65200
      admin-state enabled
      passive enabled
      update-source bundle-Y.999
      ebgp-multihop 10
      local-as <peer_as> type no-prepend
      {%- for afi in selected_afis %}
      address-family {{ afi }}
        send-community community-type both
        soft-reconfiguration inbound
        admin-state enabled
      !
      {%- endfor %}
    !
  !
!
```

### ExaBGP Config (conf.ini)

Generated by `bgp_tool.py` from Jinja2 template or inline. Family names: `ipv4 flow`, `ipv4 flow-vpn` (NOT flowspec).

## Validation

Always run `validate_config(device_name, config_text)` before apply.

## Apply Sequence

1. DNAAS leaf first (extends bridge-domain)
2. Target device second (adds sub-interface, route, BGP neighbor)
3. Store in `sessions/<id>.json` with rollback commands

## Step: Device iptables for BgpTrius (NSR devices)

DNOS devices with NSR active run **BgpTrius**, which installs iptables rules that DROP all TCP port 179 traffic without mark `0x65179`. External peers like ExaBGP are blocked because their SYN-ACK packets arrive with mark 0.

**Detection:** If session stays in `Connect` after 30s and ExaBGP shows `listening on 0.0.0.0:179`, SSH to device shell and check:
```
run start shell
password: dnroot
iptables -L INPUT -n --line-numbers | head -15
```
If you see DROP rules for `tcp dpt:179` and `tcp spt:179` with `mark match ! 0x65179`, the device needs ACCEPT rules.

**Fix (SSH to device shell via paramiko):**
```
iptables -I INPUT 3 -p tcp -s <server_ip> --sport 179 -j ACCEPT
iptables -I INPUT 3 -p tcp -s <server_ip> --dport 179 -j ACCEPT
iptables -I INPUT 3 -p tcp -d <device_ip> --dport 179 -j ACCEPT
```
Replace `<server_ip>` with ExaBGP's local-address (100.64.6.134) and `<device_ip>` with the device's peering IP.

**These rules are EPHEMERAL** -- lost on NCC restart, routing-engine restart, or reboot. Re-apply after any such event.

**When to apply:** During `/BGP setup` Step 6, after ExaBGP starts and before verification. If `show bgp summary` still shows `Connect` after 30s, SSH to device and apply.

## Known Issues Checklist

| Issue | Resolution |
|-------|------------|
| ebgp-multihop required | Add `ebgp-multihop 10` under neighbor |
| Static route wrong hierarchy | Use `protocols static` NOT `routing-options static` |
| ExaBGP IPv6 parser crash | Avoid ipv6 flow/flow-vpn unless needed |
| Hold-time mismatch | DNOS default 180; set ExaBGP hold-time 180 |
| ExaBGP family names | Use `flow` not `flowspec`, `flow-vpn` not `flowspec-vpn` |
| Named pipes | Create `/run/exabgp/exabgp.{in,out}` with sudo before first run |
| BgpTrius iptables blocking | External peers blocked by NSR iptables rules. Apply ACCEPT rules. See "Step: Device iptables" above |
| incoming-ttl kills SYN-ACK TTL | Do NOT use `incoming-ttl` in ExaBGP config. It sets IP_TTL on the listener socket, not just MIN_TTL. SYN-ACK goes out with low TTL. |
| Passive mode needs privileged port | ExaBGP passive+listen 179 needs `setcap cap_net_bind_service` on Python binary. exabgp.py auto-handles this. |
